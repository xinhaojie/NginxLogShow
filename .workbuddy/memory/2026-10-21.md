# 2026-10-21

## 项目改造：HTTP 日志上报服务 → nginx 日志分析服务（对齐 nginx.futuremorph.cn）

### 需求（用户确认的方案）
- 网页配置日志路径 + log_format（存 SQLite，热生效）
- log_format 字符串编译正则 + JSON 日志自动检测，两者都支持
- 移除原 JSON 上报功能（POST /api/logs、多系统分表、IP/手机归属地代理、zstd/base64/ureq/encoding_rs 依赖）
- 完整 ECharts 仪表盘（PV/UV/流量/错误率/P95、趋势、状态码饼图、Top 路径/IP、最近错误表）

### 实现
- 新增 `src/nginx/`：`parser.rs`（log_format→正则，`$var` 按后随字符选模式：引号内 `[^"]*`、括号内 `[^\]]*`、数值 `\d+`、默认 `\S+`；未知变量入 extra JSON；JSON 行按 key 同名提取）、`watcher.rs`（tokio 后台任务，增量读取 offset 断点存 parse_state 表，轮转检测 size<offset 重读，半行不消费，watch channel 热生效）、`models.rs`
- 新增 `src/web/`（替代 log_server）：auth 保留 HMAC cookie；stats.rs（SQL 聚合，P95 用非空 request_time 行数做 OFFSET）；handler.rs（/api/stats/overview、/api/sources CRUD、/api/sources/test 末尾 256KB 试解析、DELETE /api/logs?days=、/api/db/size）
- schema：settings / access_logs / parse_state
- 前端 static/index.html 全新仪表盘（ECharts CDN + 配置弹窗 + 明暗主题，theme key: nginxlog.theme.v1）

### 关键环境事实
- **本机 Windows 无 cargo，编译必须走 WSL Debian**：`wsl.exe -e bash -lc "cd /mnt/e/self_develop/rust/nginx_log_rs && cargo ..."`（cargo 1.98，/root/.cargo/bin）
- WSL 的 /tmp 在会话结束后清空，测试文件要放 /mnt/e 下
- git-bash 与 WSL 的 /tmp 不互通；curl cookie 用项目内路径
- wsl 中 pkill/pgrep -f 会匹配自身命令行，用 -x 精确进程名
