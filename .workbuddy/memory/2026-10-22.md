## 重解析「配置丢失」排查（实为解析任务静默死亡）

- 现象：用户点重解析后以为站点/格式配置丢了。排查结论：**配置从未丢失**（settings 表完好，updated_at 停在最后一次保存；实时 API 也返回完整配置），真正问题是**后台解析任务静默死亡**——实例启动 23 分钟 parse_state 一直空、access_logs 0 行、配置热生效通知毫无反应。
- 根因：`state.rs` 里 `tokio::spawn(watcher::watcher(...))` 的 JoinHandle 被丢弃，watcher future panic 会被静默吞掉（panic 信息只到 stderr，不进 flexi_logger 文件），Web 接口照常工作——解析却永久停止。具体 panic 点未知（用户 musl release 实例，我的 debug 复现跑完了全量+重解析均正常）。
- 排查手段沉淀：实例自身日志在 `logs/app_*.log`（flexi_logger，双实例共用同一目录会互相混写）；`/proc/<pid>/fd` 可确认打开的 DB/日志文件；tokio 线程全 S 且 CPU≈0 → 任务死而非忙。
- 修复（watcher.rs / handler.rs / index.html）：
  1. **panic 防护**：`parse_round_guarded` + 重解析分支均 `catch_unwind(AssertUnwindSafe)`，panic 记 error 日志后任务继续；`panic_msg()` 提取消息。
  2. **解析进度实时落库**：`parse_source` 每flush一批（5000 行）就 upsert parse_state（offset + lines_total 实时涨）。此前只在整轮结束才写，62MB 文件在 /mnt/e（drvfs）全量解析约 4-5 分钟，期间页面显示「尚未解析」、统计全 0，用户会以为坏了。
  3. **save_sources 清理孤儿 access_logs**：原来只清孤儿 parse_state，删掉的源遗留数据行永远查不到也删不掉（用户库里有旧源 id=1 的 35 行孤儿）。
  4. 前端重解析确认框加提示「大文件解析需要几分钟，进度会实时增长」。
- 实测：全量解析 190623 行（失败 2080），解析中 lines_total 15s 内从 1.5万 涨到 8.5万，进度可见；`cargo test` 11 过。
- 注意：`pkill -f 'target/debug/nginx_log_rs'` 会匹配 WSL bash -lc 自身命令行把 shell 杀掉（exit 15），用 `pkill -x nginx_log_rs`。

## IP 归属地接口切换为 pconline

- 用户要求换接口：`https://whois.pconline.com.cn/ipJson.jsp?ip=<ip>&json=true`（GBK 编码、单 IP 查询、无 batch）。字段映射：国内 pro=省/city=市/addr 去省市前缀余量=ISP（country 固定「中国」）；海外 pro 空、addr（如「美国」）作 country。
- **实测限速**：连续 ~16 次快速请求即 503（`Service Temporarily Unavailable`）→ 空响应封锁，且封锁期反复探测会持续封锁；~60s 静默后恢复。
- **关键网络发现**：WSL 直连 pconline:443 TLS 握手能过但 HTTP 层被断开（ureq/rustls 与 openssl s_client 直连都不返回响应）；只有走本机代理 `http://127.0.0.1:10808`（curl 曾走 env 代理成功）。代理 env（HTTPS_PROXY）时有时无不可靠 → **做成 config.toml `[server] ip_geo_proxy`**（已填 127.0.0.1:10808），回退 HTTPS_PROXY/ALL_PROXY env，main.rs 启动 `ip_geo::init()` 注入全局 OnceLock → LazyLock Agent。
- 依赖变更：ureq features 加 `tls`（rustls，musl 可静态编译，rusqlite bundled 本就需要 cc 所以工具链没问题）+ 新增 `encoding_rs`（GBK 手动转码，不用 into_string 的 UTF-8 校验）。
- 限速兼容实现（`ip_geo.rs` FetchGate 全局状态）：滑动窗口 15 次/60s + 最小间隔 500ms + 单次接口调用最多同步外查 8 个（其余下次补查）；失败（503/空响应/非 JSON）进冷却 60s 起指数翻倍封顶 15 分钟，冷却期不外查不写缓存；失败 IP 不写空缓存（区别旧策略），下次自动重试。
- 修复：私网 IP 处理挪到外查之前（原来排在外查失败 break 之后会被连带跳过）。
- 端到端验证（走代理）：114.114.114.114→中国/江苏省/南京市/电信、8.8.8.8→美国、1.2.4.8→中国/北京市、192.168.1.1→内网/保留地址；失败后 70s 冷却过期自动补查成功。12 个单测全过（新增 pconline JSON 解析 + 冷却退避测试）。
- 老坑复现：`cargo test` 不更新主二进制，端到端前必须 `cargo build`（Build 时间戳确认）。
- doc/api.md 3.5 节与第 5 节配置表同步更新。
